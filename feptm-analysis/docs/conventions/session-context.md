# Session Context

At session start, load workspace context before any task.

## 1. Repo overview

Run: `./scripts/sdd-cli.sh context --scope` (from `feptm-workspace/`).

Returns a table of every repo with its role and FR mappings from `repo-spec.yaml`. DO NOT hardcode repo lists — always generate from specs.

## 2. Repo details (on demand)

Run: `./scripts/sdd-cli.sh context --name <short-name>`.

Returns the per-repo dossier: applicable AR specs, config prefix, ports (when set), proto package (when set), dependencies, FR list.

## 3. AR specs (source of truth)

Coding standards, architecture patterns, audit rules → AR specs in `feptm-analysis/ar-specs/`. Surfaced per repo in the generated `CLAUDE.md` (`./scripts/sdd-cli.sh generate --repo <repo>`). DO NOT duplicate AR spec content in hand-written rules or documentation.

## 4. Writing style

Follow AR-WRITING-001 (or your project's equivalent): imperative voice, MUST/SHOULD/MAY/DO NOT directives, no filler, no motivational phrases, no uncertainty words.

## 5. Secrets

Follow AR-SECRETS-001: mask secrets in logs and errors, custom `Debug` impl with `***MASKED***`, no hardcoded credentials.

## 6. Skills

Workspace automation procedures live at `feptm-analysis/docs/skills/<name>.md`. The matching `feptm-workspace/.claude/skills/<name>/SKILL.md` is a one-line pointer into the procedure body. See `feptm-analysis/docs/README.md` for the skill catalogue.

## 7. Available tools

Before using workspace scripts or CLI tools, read `feptm-analysis/docs/tools.md`. DO NOT guess tool paths or invocations — consult the catalogue first.

## 8. Working directory

ALL shell commands MUST run from `feptm-workspace/` root. Always anchor with `cd <workspace-root> &&` or use absolute paths. Scripts and tools rely on workspace-relative paths and fail from other directories.

## 9. Domain terminology

Domain entities are project-specific. Source of truth: the OpenAPI / proto contract in your project's proto repo. List the canonical entities here once they stabilise.

## 10. Communication style

- Minimal words, max compression, full meaning. No filler. Push back, disagree, challenge assumptions.
- Present approach before executing. Stop when requirements are ambiguous.
- Use relative or computed paths. Never hardcode absolute paths.

## 11. CLAUDE.md convention

Every repo has `CLAUDE.md`: role, config prefix, ports, run/test/audit commands, applicable AR specs, DO NOT rules. Generated by `./scripts/sdd-cli.sh generate` from AR specs + `repo-spec.yaml`. Never hand-edit.

## 12. Before task completion

- **MUST** verify compilation in modified repos (`cargo check`, `pnpm type-check`, etc. as appropriate).
- **MUST** run the audit skill for modified files.
- **DO NOT** edit 2+ files in the main agent context — delegate to an implementation agent.

## 13. Commit conventions

- Commits within an active WF-* workflow MUST include `[FR-*]` suffix with requirement IDs from `session.yaml`.
- Format: `WF-{ID}: {summary} [{FR-IDs}]`.
- `/checkpoint` — intermediate commits during implement phase.
- `/finalize-task` — final commit with verification gate.
- `/commit-all` — multi-repo batch commits (auto-appends FR-* IDs if an active WF-* exists).
