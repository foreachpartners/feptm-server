# feptm workspace

This folder is the workspace repo of feptm. It hosts the agent harness and scripts.

## Session Context — MANDATORY

**BEFORE answering the first user message**, execute these steps. Non-negotiable, even for trivial requests:

1. Read [`../feptm-analysis/docs/conventions/session-context.md`](../feptm-analysis/docs/conventions/session-context.md).
2. Follow the procedure: run `./scripts/sdd-cli.sh context --scope` for the repo overview.
3. Only then respond to the user.

## Skills invocation

Read `SKILL.md` in `.claude/skills/<name>/` → follow the link to the procedure body in `../feptm-analysis/docs/skills/<name>.md`. The procedure is the source of truth; the SKILL.md is a callable handle.

For OpenCode, skills live at `.opencode/skills/sdd-*.md` — invoke with `run sdd-<name>`.

## Commit conventions

- Commits within an active WF-* MUST include `[FR-*]` suffix with requirement IDs from `session.yaml`.
- Format: `WF-{ID}: {summary} [{FR-IDs}]`.
- `/checkpoint` — intermediate commits during implement phase.
- `/finalize-task` — final commit with verification gate.
- `/commit-all` — multi-repo batch commits (auto-appends FR-* IDs if active WF-* exists).

## Layout

- `../feptm-server/` — Python/FastAPI service (uv + uvicorn). Config prefix: `FEPTM_FEPTM_SERVER__`.
- `../feptm-analysis/` — FR specs (`fr-specs/`), AR specs (`ar-specs/`), `naming-convention.yaml`, `role-templates.yaml`, and `docs/` (narrative + skill procedures + always-on conventions).
- `./` (this folder) — agent harness (`.claude/skills/`, `.opencode/skills/`), shell scripts (`sdd-cli.sh`), and `repo-spec.yaml` (carries `role: workspace`).

Skill procedures and always-on conventions live as plain Markdown under `../feptm-analysis/docs/{skills,conventions}/`. `./.claude/skills/<name>/SKILL.md` is a thin pointer (≤8 lines) into the corresponding doc; never inline a procedure into SKILL.md.

## fep-sdd consumption

This project consumes `fep-sdd` from a sibling clone — `scripts/sdd-cli.sh` resolves to `../../../fep-sdd/` from this folder's `scripts/` (so a checkout layout of `<dir>/{fep-sdd,feptm}/` works out of the box). Override with the `FEP_SDD_DIR` env var if the CLI lives elsewhere.

```bash
./scripts/sdd-cli.sh context --list-names
./scripts/sdd-cli.sh context --scope
./scripts/sdd-cli.sh audit --files ../feptm-server/src/main.py
./scripts/sdd-cli.sh audit --mode full --files ../feptm-server/src/main.py
./scripts/sdd-cli.sh generate --repo ../feptm-server --dry-run
```

The wrapper invokes `uv run --project <fep-sdd-dir> fep-sdd ...`.

## What is enforced

`../feptm-analysis/ar-specs/` ships AR specs that define coding standards, architecture patterns, and audit rules. See the generated per-repo `CLAUDE.md` for each repo's applicable AR specs.

Role-to-rule mapping lives in `../feptm-analysis/ar-specs/role-templates.yaml`. A repo's `repo-spec.yaml` declares its `name` and `role`; the resolver expands that into the full applicable AR-spec set, plus all `always_apply` specs.

## DO NOT

- Hand-edit per-repo `CLAUDE.md` (generated by `fep-sdd generate` from AR specs + repo-spec.yaml). Regenerate instead.
- Duplicate AR spec content in hand-written rules or documentation. Link to `feptm-analysis/ar-specs/`.
- Hardcode absolute paths in scripts — resolve from $0 or use workspace-relative paths.
- Invoke `sdd-cli audit` directly in the main agent — use the audit skill instead.
